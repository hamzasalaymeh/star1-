## 2. قاعدة ذهبية: استخدم `contains()` دائماً

أسماء ASP.NET الكاملة تبدأ ببادئات متغيّرة مثل
`ctl12$TemplatePage$GridView1$...`. لكن الجزء المميّز (`ctl37$Field1$ctl03`)
ثابت. لذلك **كل محدّدات الحقول تستخدم `contains()` وليس تطابقاً كاملاً**:

```python
# صحيح — يصمد حتى لو انزاحت الحقول تحت TemplatePage
driver.find_element('xpath', "//input[contains(@name,'ctl37$Field1$ctl03')]")

# خطأ — ينكسر عند أي تغيير في البادئة
driver.find_element('xpath', "//input[@name='ctl37$Field1$ctl03']")
```

هذا هو سبب بقاء حقول صفحة التعديل شغّالة رغم أن المنصة نقلتها تحت
`ctl12$TemplatePage$GridView1$`.

## 4. صفحة تعديل المبنى (DataEdit/{ID}/2)

الحقول المهمة للأتمتة (الإحداثيات + المساحة + صورة الكروكي):

| الوظيفة | المحدّد (contains) | QuestionId | النوع | مثال قيمة |
|---------|--------------------|------------|-------|-----------|
| **X — خط الطول (longitude)** | `ctl37$Field1$ctl03` | 320 | text | `42.08571` |
| **Y — خط العرض (latitude)** | `ctl38$Field1$ctl03` | 321 | text | `19.264981` |
| **المساحة** | `ctl39$Field1$ctl03` | 316 | number | `49` |
| **صورة الكروكي (رفع)** | `ctl40$Field1$ctl27` | 315 | file | — |
| صورة الكروكي (اسم الملف المرفوع) | `ctl40$Field1$ctl28` | 315 | text | يظهر مسار الملف بعد الرفع |
| **زر الحفظ** | `ctl12$btnSave` | — | submit | «حـفــظ بيانــات الاستمـــارة»، id=`ctl12_btnSave` |
| اسم المبنى (للعرض/التحقق) | `ctl12$RequestBasics$ctl19` | — | text | «مبني رقم 2 في قرية الغرة 1» |

### منطق رفع الملف
لكل حقل ملف `ctlNN$Field1`:
- `ctlNN$Field1$ctl27` = `<input type=file>` (المخفي — نرفع عليه)
- `ctlNN$Field1$ctl28` = `<input type=text>` يعرض اسم الملف الحالي
  («لا يوجد» = فارغ). نتحقق من الرفع بأن قيمته تغيّرت وصارت غير فارغة.
- `ctlNN$Field1$ctl31` = رابط حذف الملف القديم (إن وُجد).

### حقول ملفات أخرى على نفس الصفحة (للعلم — لا نلمسها)
| المحدّد | QuestionId | النوع | ملاحظة |
|---------|------------|-------|--------|
| `ctl34$Field1$ctl27/28` | 272 | File | كان فارغاً («لا يوجد») |
| `ctl35$Field1$ctl27/28` | 314 | File | فيه ملف مسبق |
| `ctl36$Field1$ctl27/28` | 317 | File | فيه ملف مسبق |

### بنية الأسئلة الديناميكية
الصفحة عبارة عن `GridView1` من «أسئلة»، كل سؤال في `ctlNN$Field1` وله:
- `hdnQuestionId` = رقم السؤال الثابت (مرجع مستقر عبر كل المباني)
- `hdnQuestionType` = نوعه: `Text` / `Number` / `File` / `Radio` / `Check` / `BigText` / `None`
- `ctl03` = حقل الإدخال للنصوص والأرقام
- `ctl18$i` = خانات اختيار (Check) | `ctl23` = أزرار راديو (Radio)

> **نصيحة مهمة:** إذا أعادت المنصة ترتيب الأسئلة مستقبلاً وتغيّرت أرقام
> `ctlNN`، فإن **QuestionId يبقى ثابتاً**. الأضمن مستقبلاً = إيجاد الحقل
> عبر QuestionId: ابحث عن `hdn...$hdnQuestionId` قيمته = الرقم المطلوب
> (320 للطول، 321 للعرض، 316 للمساحة، 315 للكروكي)، ثم خذ `ctl03`/`ctl27`
> من نفس `Field1`.

## 5. ملفات الكود في المستودع

| الملف | الوظيفة |
|-------|---------|
| `upload_croquis_v5_autologin.py` | السكربت الرئيسي (v5): دخول تلقائي + بحث باسم القرية + رفع الإحداثيات والصورة + تقرير حي |
| `diagnose_heritage.py` | سكربت تشخيص: يطلّع أسماء كل الحقول من صفحتي البحث والتعديل إلى `heritage_fields.txt` |
| `upload_croquis_simplified.py` | نسخة قديمة مبسّطة (بحث برقم المبنى — غير مستحسنة) |
| `upload_croquis_auto.py` | نسخة قديمة (محدّدات مخمّنة — غير مستحسنة) |
| `heritage_docs/heritage_fields_dump.txt` | الإخراج الخام من التشخيص (مرجع الحقول) |

### خصائص السكربت الرئيسي (v5)
- **الدخول:** `auto_login()` يكتشف حقول اسم المستخدم/كلمة المرور بعدة طرق،
  يكتب البيانات ويضغط دخول، ويتحقق من النجاح. يرجع لدخول يدوي مرة واحدة لو فشل.
- **الجلسة:** Chrome ببروفايل ثابت `C:\heritage_automation_profile` على
  المنفذ `9333` — الجلسة تبقى محفوظة بين التشغيلات.
- **البحث:** باسم القرية (= اسم المجلد)، بعدة صيغ، مع فصل القرى المتشابهة
  (مثل «الماوين» ضد «الماوين بللحمر») وقراءة كل صفحات النتائج.
- **انتظار حقل البحث:** ينتظر `ctl12$ctl04` حتى 30 ثانية (حل مشكلة
  «no such element» عند بطء تحميل الصفحة).
- **المطابقة:** رقم المبنى من عمود `coded` في Excel ↔ رقم المبنى في
  اسم الموقع بالمنصة. الأعمدة: `خط_الطول_X` / `خط_العرض_Y` / `المساحة`.
- **تطابق الصور:** يأخذ الرقم بعد آخر `_` في اسم الصورة (مثل
  «الغرة 1_5.png» ← المبنى 5)، لتجنّب الالتباس مع الرقم في اسم القرية.
- **الرفع والتحقق:** يكتب X/Y/المساحة، يرفع الصورة، يضغط حفظ، ثم يعيد
  تحميل الصفحة ويتحقق أن القيم حُفظت فعلاً (تصل لمحاولتين كاملتين).
- **قابل للاستئناف:** لا يعيد رفع مبنى مكتمل ومتحقّق منه مسبقاً.
- **التقرير:** `تقرير_المتابعة_YYYYMMDD_HHMMSS.xlsx` يُحفظ بعد كل مبنى
  (شيت «سجل المواقع» + شيت «ملخص القرى»).
- **زر إيقاف مؤقت عائم** + إعادة اتصال تلقائي بعد نوم الجهاز.

## 7. طريقة إعادة الاكتشاف لو تغيّرت المنصة مستقبلاً

1. شغّل `diagnose_heritage.py` (بعد تسجيل الدخول).
2. افتح أي مبنى على صفحة «استكمال بيانات الميدان» قبل الضغط Enter للخطوة الثانية.
3. افتح `heritage_fields.txt` وطابق القيم المعروفة:
   - الحقل الذي قيمته تشبه `42.xxxxx` → **X**
   - الحقل الذي قيمته تشبه `19.xxxxx` → **Y**
   - حقل `type=number` بقيمة المساحة → **المساحة**
   - حقل `type=file` فارغ بجانب كروكي → **صورة الكروكي**
4. أو طابق عبر QuestionId الثابت (320/321/316/315).
5. حدّث المحدّدات في `upload_croquis_v5_autologin.py` إن لزم.
